# FM-D-ASSERTBYPASS

Provisional (candidate-anchored) -- not listed in `failure-modes/INDEX.md`, per the `requirements-enforcement` skill's bootstrapping/provisional convention. Holds instances as accruing evidence; generates no obligations until the anchoring guarantee is ratified.

## Mode: FM-D-ASSERTBYPASS.CONFIDENT-UNCITED-CLAIM

**Mechanism.** `no-silent-assumptions-software-planning`'s Stage-0 Routing Gate classifies every **candidate question** into Factual-unknown / Agent-resolvable / Genuine-user-decision, and routes Outcome-1 (factual) to Analyst delegation instead of the user. The gate's trigger condition is "classify each candidate question" -- but a Planner mid-conversation frequently states the ANSWER directly, as a confident declarative claim ("these two fixes are what's structurally required", "same end state, sequenced", "X is the only viable choice"), rather than posing it as a question first. Because the sentence was never framed as a question, it never enters the Stage-0 classifier at all -- even when its content is a textbook Outcome-1 factual unknown (discoverable by reading code, tracing a producer, or executing a check). The failure is not that the routing rule is wrong; it is that overconfidence lets the Planner skip the gate entirely by answering instead of asking. The resulting pattern, reported directly by the user this repo serves: the Planner states an unverified claim -> the user has to notice the missing evidence and push back -> an Analyst delegation (the exact mechanism the budget exists to spend proactively) then resolves it with evidence -> the open question "evaporates," having cost the user a full challenge-and-wait cycle the budget was supposed to prevent. User's own words: "Analyst delegations associated with plan creation are provided to prevent exactly this sort of loop. This is a waste of my time," and "they happen with almost every plan" (frequency is user-reported, not corpus-measured -- see Oracle).

A second, narrower variant of the same root cause: a "genuine user decision" (Stage-0 Outcome-3, correctly routed to the user) can still carry embedded factual sub-claims inside its own framing or scorecard cells (a cost estimate, a capability-equivalence claim) that are themselves Outcome-1-shaped but never independently checked, because Stage-0 classifies at the whole-question level, not the cell/claim level. The enclosing question being legitimately Stage-1-worthy does not make every fact embedded in its rationale correct-by-association.

A third variant (`.004`), the **authority-frame slide**: rather than a single discrete uncited claim, the agent adopts a _role-label_ for an artifact -- "the reference," "the oracle," "the authority," "the trusted X" -- whose authority-SCOPE is never specified, so a _relative_ property (e.g. "faithful sibling of the generated code") silently reads as an _absolute_ one ("authoritative about correctness"). The slide persists across many turns because no single sentence looks like an unverified claim, and it is reinforced when the artifact's NAME already sounds authoritative ("oracle") -- the name does the agent's thinking. The authority question ("what does X validate against?") is itself a textbook Outcome-1 factual unknown the Stage-0 gate would route to grounding IF it were ever posed -- but a role-label is adopted, not asked. Two candidate detections/mitigations raised by the user this repo serves, recorded here for a human to weigh (not yet designed or ratified): (a) a **frame-check trigger** -- the second time an agent leans on one artifact as "the reference / authority / trusted X," it must answer "authority over WHAT, validated against WHAT?" and ground that (an up-front Analyst delegation) before building further advice on it; (b) an **oracle/reference qualifier convention** -- require "oracle-of-WHAT / validating-WHAT" at first use of such a role-label, so the authority scope is named rather than assumed. The user notes this category "has happened before within plan creation and execution -- many times," with the trajectory not previously traced back to these insights.

**Oracle.** `--` (provisional; no oracle designed yet -- this is a judgment/discipline gap, not a mechanically greppable pattern; a candidate detection approach would need an LLM-graded pass over a Planner transcript classifying each declarative claim as cited-or-verified vs. asserted, which has not been designed or piloted).

**Disposition.** Recorded as evidence only, at the user's direct request (2026-09-25), specifically so this class is visible to every consuming repo/session rather than re-discovered privately per project. A structural, instruction-level mitigation was authored the same session: `no-silent-assumptions-software-planning/SKILL.md`'s new "Unquestioned Assertions (Assertions-as-Answers)" subsection (Stage-0 section) extends the classifier's trigger condition from "candidate questions" to "any confident, uncited claim," with a self-check trigger rule. Whether this becomes a ratified guarantee, and whether a real oracle can be designed for it, is ledger work for a human to weigh, not decided here — the user has explicitly declined mini-retro-based tracking/review of individual occurrences ("I don't need to review these, they happen with almost every plan"), so this class file plus the SKILL.md rule change are the intended durable artifacts, not a review queue.
